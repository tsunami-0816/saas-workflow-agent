## 一、待核对清单逐项结论

### ① python→java `/internal/llm/chat` 缺 X-Tenant-Id 头 → 额度扣减跳过 【已修复并验证】

**实测证据（修复前）**：
- curl 不带租户头调 `/internal/llm/chat` → `llm_call_log` id=1 `tenant_id=0`（占位），`tenant_quota.token_used` 不动；
- java 日志实证：`WARN LlmRouterService - llm call without tenant context, quota skipped taskType=agent_reasoning`；
- 带 `X-Tenant-Id: 1` 对照 → id=2 `tenant_id=1`，`token_used=14`（4+10 精确扣减）。

**根因（双侧契约遗漏，全链 4 处断点）**：
1. java `AgentNodeExecutor` 未把 `ctx.getTenantId()` 放进 `/agent/run` 请求体；
2. python `AgentRunRequest` 无 `tenantId` 字段；
3. python 图状态 / `JavaGatewayLLM` 无租户透传；
4. python `JavaLLMClient.chat()` 不发 `X-Tenant-Id` 头。

**修复（5 文件，仅租户透传，不动其他逻辑）**：
- `AgentNodeExecutor.java`：body +`tenantId`；
- `schemas.py`：`AgentRunRequest` +`tenant_id`（可选，camelCase 自动转换）；
- `graph.py`：`AgentState` +`tenant_id`，`initial_state` 透传，三角色节点 `_make_llm` 传入；
- `crew_llm.py`：`JavaGatewayLLM` +`tenant_id`，call 时传给 client；
- `llm_client.py`：`chat()` +`tenant_id`，非 None 时带 `X-Tenant-Id` 头。

**验证（修复后，e2e）**：`POST /agent/run {tenantId:1}` → SUCCESS（planner/executor/reviewer 三步）→ `llm_call_log` id=3/4/5 全部 `tenant_id=1`；`token_used` 14→365，增量 351 = (94+10)+(103+10)+(124+10) 精确吻合。✅

### ② `/agent/run` 恒 200 + status 成败口径 【核对通过】

- 成功路径：HTTP 200 + `status=SUCCESS` + output/reasoning 完整（见①验证）；
- 失败路径实测：`taskType=nl2flow`（路由 deepseek 无 key）→ **HTTP 200** + `status=FAILED` + `error` 非空 + 推理链含失败断点（`planner: LLMGatewayError(... code=40001 DEEPSEEK_API_KEY 未配置)`），链路短路不再执行后续节点；
- java 侧 `AgentNodeExecutor` 读 `status` 字段判败 → `NodeResult.fail` → 引擎写 retry_log。两侧契约一致。✅

## 二、附带发现并已修复：内部令牌配置漂移

`agent-python/.env` 的 `INTERNAL_API_TOKEN=swa-dev-only-...` 与 java 运行时默认值 `dev-only-internal-token` 不一致，任何 python→java LLM 调用恒 401（curl 实测）。第 6 步主流程无 agent 节点故未暴露。
**修复**：java 启动命令补 `INTERNAL_API_TOKEN` 环境变量对齐 .env（配置修复，无代码变更）。同时 java 启动加 `LLM_ROUTE_AGENT=openai-mock` 以便无真实 key 时跑通 agent 链路（设计内配置旋钮）。
