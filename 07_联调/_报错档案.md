# 第 7 步报错档案（2026-10-31）

> 按 `appendixA` A-0a 格式，报错当场记录。原始证据：`evidence/1031/link_result.json`（首轮运行已覆盖为复跑结果，首轮失败明细见下）。

## [10-31 21:44] Redis 查询报 NOAUTH
- 命令：`docker exec rag-redis redis-cli -n 3 GET quota:remain:1`
- 报错：`NOAUTH Authentication required.`
- 根因：6379 端口上同时有原生 Redis（无密码，后端实际使用）与 Docker rag-redis（有密码 123456、属其他项目）；连错实例。
- 修复：改用 `python` + `redis` 库连 `127.0.0.1:6379 db3`（原生实例），不涉及代码/配置改动。
- 关联：检查清单 §六 环境说明；无台账条目（非产品问题）。

## [10-31 21:49] L-03 环用例返回 20004 而非 20002
- 命令：`POST /api/v1/workflows/{id}/versions`，DSL `t1(mqtt-trigger)→c1(condition)→t1`
- 报错：`code=20004`（期望 20002 环形依赖）
- 根因：`DslValidator` 先校验「mqtt-trigger 入度必须为 0」，再走 Kahn 环检测；用例把回边指到触发器，命中了入度规则。属用例构造缺陷。
- 修复：改用 `t1→delay1→delay2→delay1`（环不含触发器入边），复跑返回 20002。
- 关联：失败日志 #36；台账无（脚本缺陷）。

## [10-31 21:49] L-05 SSE 读流抛 ReadTimeoutError
- 命令：`GET /api/v1/executions/{id}/events`（stream，timeout=8）后 `iter_lines`
- 报错：`ConnectionError(ReadTimeoutError(127.0.0.1:8083))`，中断后续 false 分支/回放断言
- 根因：SSE 为长连接，事件停发后客户端读超时属预期行为，用例未捕获。
- 修复：`except requests.exceptions.RequestException: pass`，保留已收集事件后继续断言。
- 关联：失败日志 #36；台账无（脚本缺陷）。

## [10-31 21:49] L-06 延时总时延断言越界（2.13s < 2.5s）
- 命令：同上联调脚本 L-06（delayMs=3000）
- 报错：`✗ 恢复时延 2.5~20s :: 2.13s`
- 根因：计时基线取在 `sleep(1.2)` 之后，漏计前 1.2s，实际总时延约 3.3s 属正常。
- 修复：`t_create` 提前到创建执行前，断言改为「创建→终态总时延」，复跑 3.46s 通过。
- 关联：失败日志 #36；台账无（脚本缺陷）。

## [10-31 21:49] L-10 订阅停用返回 10000 且停用后仍触发
- 命令：`PUT /api/v1/mqtt/subscriptions/{id}` body `{"status":"inactive"}`
- 报错：`code=10000`（参数错误），随后发消息仍新建执行 `28->29`
- 根因：`MqttSubscriptionRequest` 的 `@Pattern(regexp="active|disabled")` 只允许两值，`inactive` 非法，更新失败故订阅仍 active。
- 修复：改为 `status:"disabled"`，并加断言返回体 status=disabled；复跑停用后 `36->36` 无新执行。
- 关联：失败日志 #36；台账无（脚本缺陷）。
