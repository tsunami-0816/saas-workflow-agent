### 8.1 真实根因（faulthandler 栈）

证据文件：`06_冒烟\crewai_import_trace.log`（`dump_traceback_later(25, exit=True)` 实测产出）

```
Timeout (0:00:25)!

  File "...\Lib\tempfile.py", line 257 in _mkstemp_inner
  File "...\agent-python\.venv\Lib\site-packages\crewai_core\settings.py", line 98 in get_writable_config_path

  File "...\crewai\events\listeners\tracing\trace_batch_manager.py", line 88 in __init__

```

**根因**：卡点不在 chromadb/lancedb、不在网络、不在 stdin，而是 crewai **import 期**构造
`TraceBatchManager → PlusAPI → Settings()` 时，对 `~/.config/crewai` 做 `tempfile.mkstemp` 写探测
（`get_writable_config_path` 逐个探测 `~/.config/crewai` → TEMP → cwd）。该目录下的**创建式打开在本机受限环境会长期阻塞且不抛异常**，
crewai 的 fallback 只在捕获到异常时才降级，因此永远不会走到 TEMP/cwd → `import crewai` 卡死（CPU≈0、无输出）。

**对照实验（同一命令，排除猜测）**：

| 实验 | 沙箱执行 | 非沙箱执行 |
|---|---|---|
| `os.open(~/\.config/dbg_probe.txt, O_CREAT\|O_EXCL)` | 15s watchdog 命中，栈停在 `_mkstemp_inner`（`06_冒烟\dbg_home_cfg.log`）| 瞬时 `OPEN_PARENT_OK`（`dbg_open_parent_nosandbox.log`）|
| `tempfile.mkstemp(dir=%TEMP%)` | 瞬时 `MKSTEMP_OK` | — |

→ 判定为「受限目录写入策略导致的阻塞」，非 crewai bug、非业务代码 bug。
