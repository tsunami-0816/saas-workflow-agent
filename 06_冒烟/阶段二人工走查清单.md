## S3 画布编排（6 类节点 + 连线 + 分支标记）

1. 列表点「画布」进入编辑器。
2. 从左侧节点面板依次拖入 6 个节点，右侧面板改名称：
   - MQTT 触发 → `t1` 温度采集（无需配置）
   - 条件分支 → `c1` 高温判断，表达式 `t1.payload.temp > 80`
   - HTTP API → `h1` 告警通知，URL `http://127.0.0.1:8083/actuator/health`，Method `GET`，timeoutMs `10000`
   - 代码块 → `d1` 正常记录，表达式 `'normal: ' + t1.payload.temp`
   - 延时 → `delay1` 延时30秒，delayMs `30000`
   - Agent 任务 → `a1` 智能研判，task 填「用中文一句话总结本次温度读数并判断是否需要告警」，taskType 留空
3. 连线（从节点**底部圆点**拖到目标节点**顶部圆点**）。`t1`/`c1` 等是节点编号（右侧「节点名称」可改成中文），`→` 表示从前者连到后者：

```
t1(MQTT触发) → c1(条件: t1.payload.temp > 80)
   c1 --true-->  h1(HTTP)  → delay1(延时30秒) → a1(Agent)
   c1 --false--> d1(代码)
```

   对照表：

| 写法 | 白话 |
|---|---|
| `t1→c1` | 采集到的温度交给条件判断 |
| `c1→h1(true)` | 条件成立（温度>80）走 h1 |
| `c1→d1(false)` | 条件不成立走 d1 |
| `h1→delay1` | 告警发完后进入延时 |
| `delay1→a1` | 延时结束进入 Agent |

   跑起来只有一条路：`{"temp":95}` → c1 为 true → h1 → delay1(WAITING) → a1，d1 为 SKIPPED；`{"temp":60}` → c1 为 false → d1，h1/delay1/a1 全部 SKIPPED。条件节点必须拖两条出边（第一条自动标 true、第二条自动标 false，双击边可互换）。

**预期**：6 节点都在画布；条件节点两条出边分别标 `true` / `false`；节点选中时右侧出现对应配置表单。

- [ ] 通过

## 已知边界（属预期，不算错误）

- 前端没有「凭据管理」页面：连接器凭据（credentials）只有后端接口，UI 未做，属设计范围外（L-01/L-02 同类增强项）。
- Agent 节点耗时 10~60 秒，属真实 LLM 调用，不是卡死。
- 延时 30 秒是配置值，想更快可在画布把 delayMs 改小（最小 1000）。
- 走查期间重启后端，会把 WAITING 执行收敛为 FAILED（failReason=engine_restart），这是 BE-4.10 设计行为。
