## 一、八段结构（正文）

### A 一句话

多租户 SaaS 工作流编排平台：Spring Boot 3 + LangGraph + Vue3/X6，12 表 / 27 接口 / 6 类节点。

### S 背景

中小团队的告警处置流程（设备高温 → 生成话术 → 写看板 → 通知销售）长期依赖研发排期。约束：16GB 内存单机、单人开发、不引入 BPMN 与微服务全家桶。

### T 目标（括号内为最终实测）

1. 画布 ≥30 节点含条件分支，保存/重载不丢配置（M1 通过）。
2. 同一流程 ≥100 实例并发，上下文不串租户（M2 通过）。
3. 20 条自然语言需求生成流程，结构合法且语义可用 ≥14 条（M5 实测 19/20）。

### A 动作

1. **自研 DAG 引擎**：拓扑调度、条件分支、指数退避重试 ≤3、RabbitMQ 异步、SSE 推送、重启 sweeper。不引 Flowable——本项目只有分钟级短流程，没有人工任务与长事务补偿需求，可省掉 30+ 张 BPMN 表。落在 [ExecutionEngine.java](file:///D:/lg/project/工作流测试/projects/saas-workflow-agent/05_代码/backend/src/main/java/com/swa/backend/engine/ExecutionEngine.java)。
2. **多租户隔离**：tenantId 只从 JWT claim 取，MyBatis-Plus 租户拦截器统一注入 SQL；MQ Worker / sweeper 显式 `TenantContext.set` 并在 `finally` 清理，无上下文时落 `tenant_id=0`（查不到，而不是查到别人）。落在 [MybatisPlusConfig.java](file:///D:/lg/project/工作流测试/projects/saas-workflow-agent/05_代码/backend/src/main/java/com/swa/backend/config/MybatisPlusConfig.java)。
3. **防重复与额度**：Redis `SETNX`（userId + versionId + clientReqId，TTL 24h）保证重复点击返回同一 executionId；额度用 Lua 脚本原子「初始化 → 判断 → DECRBY」。落在 [ExecutionService.java](file:///D:/lg/project/工作流测试/projects/saas-workflow-agent/05_代码/backend/src/main/java/com/swa/backend/service/ExecutionService.java)、[LlmRouterService.java](file:///D:/lg/project/工作流测试/projects/saas-workflow-agent/05_代码/backend/src/main/java/com/swa/backend/llm/LlmRouterService.java)。
4. **Agent 侧**：FastAPI + LangGraph `planner→executor→reviewer` 三节点状态机；LLM 调用统一回调 Java `/internal/llm/chat`，provider 路由、token 计量、额度扣减在 Java 收口，Python 不直连数据库。
5. **前端**：Vue3 + TS + AntV X6 六类节点画布；SSE 断线后先拉 `node_execution` 快照再续订，避免只靠事件流丢状态。

### R 结果（全部实测）

- 自动化：pytest **57 passed / 0 failed**（105.08s）；基线 **M1~M8 8/8**。
- M5：DashScope `qwen-plus` 真调 20 条，**19/20**（17 成功、2 条正确拒绝、1 条结构缺陷）。
- 可靠性：HTTP 节点 100 次 **100/100**；MQTT 端到端 **P95 = 78ms**（目标 ≤3s）；条件双分支互斥（temp=95/25 各走一支）。
- 性能（本机单实例，50 并发 × 10s）：**TPS 815.1，P95 116.3ms，错误率 0%**；10/20 并发 TPS 637.7/671.9。
- 安全：**P0 = 0 / P1 = 0**；验收接口 28 项 + UI 6 项全通过；核心链路单次执行 17s，含 Agent 真调时 36s。
- **未验证**：JMeter 双工具交叉压测（本机未安装）、Edge 浏览器、全容器化端到端部署。

### C 关键词（三档，对齐 `00_JD对账表.md`）

- **用过**：Java 17、Spring Boot 3.2、MyBatis-Plus、MySQL 8、Redis（Lua / SETNX）、RabbitMQ（TTL / DLX）、JWT + RBAC、MQTT（Mosquitto QoS1）、SSE、LangGraph、FastAPI、Vue 3 + TS + Vite、AntV X6、Docker Compose（中间件）。
- **了解**：OpenAI 兼容协议、DeepSeek API（代码在、无 key 未实调）、Spring Cloud（仅 BOM）、Kafka（未接入）。
- **未用**：CrewAI（最终版按 R2 降级删除）、PostgreSQL（仅编码约束）、Qdrant / 向量检索。

### D 可演示点（均在第 9 步验收实测通过）

1. 画布拖 6 类节点（MQTT / HTTP / 条件 / Agent / 代码 / 延时）保存后重载，节点 6、边 5、`delayMs=5000` 全部还原。
2. 执行详情 SSE 实时收到 `connected` + `node` 事件；同一 `clientReqId` 重发返回同一 executionId（幂等）。
3. Agent 节点真调 `qwen-plus`，`llm_call_log` 落 6 条 token / 成本；向 `factory/line1/temperature` 发 MQTT 消息，执行实例 4→5。

### E 诚实边界

CrewAI 多 Agent 编排、Qdrant 向量检索、PostgreSQL 三项只在设计文档出现，最终版未实现，不能按「用过」讲。OpenAI / Claude 是按官方响应结构写的**协议 Mock**，只验证统一抽象 + 计量链路；DeepSeek provider 代码存在但本机无 key、未实调；OCR 连接器按架构标注砍掉；Agent 只有「规划 / 执行 / 审核」三段，没有长期记忆与工具编排。JMeter、Edge、全容器化未验证。TPS 815 是本机单实例数字，不代表生产容量；单机无 HA、无灰度、无真实计费。

## 二、可直接粘贴的纯文本（约 300 字）

多租户 SaaS 工作流编排平台（Spring Boot 3 + LangGraph + Vue3/X6，12 表 / 27 接口 / 6 类节点）。中小团队告警处置流程依赖研发排期，约束为 16GB 单机、单人开发。自研 DAG 引擎（拓扑调度、条件分支、重试 ≤3、RabbitMQ 异步、SSE 推送、sweeper）替代 Flowable；JWT claim + MyBatis-Plus 拦截器做租户隔离，后台线程显式清理上下文；Redis SETNX 幂等 + Lua 原子扣额度；FastAPI + LangGraph 三角色 Agent，LLM 统一回调 Java 路由层计量。实测：pytest 57/57、M1~M8 8/8（NL 转流程 19/20）、HTTP 100/100、MQTT P95 78ms、50 并发 TPS 815 / P95 116ms / 0% 错误、P0/P1=0。未验证：JMeter、Edge、全容器化。
