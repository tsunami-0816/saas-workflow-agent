## 3. 失败归因（3 条 40003）

### 3.1 #8 / #13：需求超出 DSL 能力边界（非缺陷）

- 需求含「失败重试」「定时轮询」，在 DSL 中只能成环，而 `DslValidator` 明令禁止环（`存在环形依赖`）。
- 校验器正确拦截并返回 `code=40003`，未落库脏数据 → **符合预期行为**，不作为产品缺陷。
- 产品层面属能力缺口（不支持重试/周期调度），登记为需求类改进项（P2/后续版本），不影响本轮验收。

### 3.2 #14：模型产出 JSON 结构非法（真实缺陷）

- 现象：`nodes` 数组第 4 个元素变成 `"h1": {...}` 键值对 → Jackson 报 `no String-argument constructor ... from String value ('h1')`。
- 定位：`NlFlowService`（prompt/few-shot → 模型输出 → `stripFence` → `DslDocument` 反序列化）；错误发生在模型输出层，非校验器。
- 已有兜底：带错重试 1 次仍失败 → 40003，前端可见错误文案，无脏数据。
- 概率：20 条样本中 1 条（5%）偶发，同一 prompt 家族其余 17 条结构正常。
- 处置：登记 Q-021（P2），建议在 prompt 中强化「nodes 必须是对象数组，禁止对象键」约束并扩充该失败样本进回归集；本轮不改代码（非 P0/P1）。
