# 第一轮技术架构设计文档 · saas-workflow-agent

## 1. 技术选型说明

| 组件 | 选型 | 版本 | 选型理由 |
|---|---|---|---|
| 后端主语言 | Java 17 + Spring Boot | 3.2.x | JD高频，流程引擎/租户/权限 |
| Agent运行时 | Python FastAPI | 0.110 | CrewAI/LangGraph生态在Python |
| Agent框架 | LangGraph + CrewAI | 最新 | JD11/JD20要求多Agent协作 |
| 消息队列 | RabbitMQ | 3.12 | 异步任务执行 |
| 业务库 | MySQL | 8.0 | 流程定义/执行记录 |
| 缓存 | Redis | 7.2 | 分布式锁/状态缓存 |
| 向量库 | Qdrant | - | RAG流程模板检索（Mock） |
| IoT接入 | EMQX MQTT | - | 设备触发（Mock） |
| 前端 | Vue3 + TS + Vite + Element Plus + AntV X6 | 3.4/2.18 | JD29要求X6工作流画布 |
| 实时推送 | SSE (SseEmitter) | - | 流程进度推送 |
| 部署 | Docker Compose | - | ≤5容器 |

## 2. 整体分层架构

```
接入层：Vue3 SPA + AntV X6画布 + SSE连接
应用层：流程管理 / 任务执行 / 租户权限 / 模型路由
服务层：DAG引擎(Java) / Agent编排(Python) / HTTP连接器 / MQTT连接器
消息层：RabbitMQ（异步任务执行）
存储层：MySQL(业务) / Redis(锁/缓存) / Qdrant(向量)
外部：DeepSeek API / OpenAI API
```

## 3. 核心业务链路

### 链路1：创建流程
```
前端X6拖拽节点 → POST /api/workflows → 存MySQL workflows表
```

### 链路2：执行流程
```
POST /api/workflows/{id}/run
  → 创建workflow_runs记录（RUNNING）
  → RabbitMQ发执行消息
  → DAG消费者拉取流程定义
  → 拓扑排序节点
  → 逐节点执行：
    HTTP节点 → RestTemplate发请求 → 记录结果
    Agent节点 → HTTP调Python服务 → 多Agent协作
    条件分支 → 按结果走下一条边
  → 每步SSE推送进度
  → 全部完成 → 状态SUCCESS
```

### 链路3：多Agent协作
```
Python服务收到任务
  → 规划者Agent：拆解任务为子步骤
  → 执行者Agent：逐步执行
  → 审核者Agent：检查结果
  → 返回最终输出
```

### 链路4：模型路由
```
请求 → 路由层判断任务类型
  → 简单任务 → DeepSeek（便宜）
  → 复杂任务 → GPT-4（强）
  → 记录Token消耗和成本
```

## 4. 数据模型

### MySQL表
**workflows**：id / tenant_id / name / definition_json / version / status
**workflow_runs**：id / workflow_id / status(RUNNING/SUCCESS/FAILED) / current_node / result / started_at / finished_at
**run_steps**：id / run_id / node_name / input / output / status / duration_ms
**tenants**：id / name / concurrency_limit
**users**：id / tenant_id / username / password / role

### Redis键设计
- `lock:run:{runId}` — 防止同一流程重复执行
- `concurrency:{tenantId}` — 租户并发计数

## 5. 接口规范

统一返回：`{ code: 0, message: "ok", data: {} }`

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/auth/login | 登录返回JWT |
| GET/POST | /api/workflows | 流程CRUD |
| POST | /api/workflows/{id}/run | 执行流程 |
| GET | /api/runs/{id} | 执行状态 |
| GET | /api/runs/{id}/stream | SSE进度流 |
| POST | /api/agent/plan | Python Agent规划 |
| GET | /api/llm/stats | Token成本统计 |

## 6. 部署架构

2. mysql:8 (宿主机3310→容器3306)
3. redis:7 (宿主机6381→容器6379)
4. rabbitmq:3 (宿主机5674→容器5672)
5. agent-python (宿主机8001→容器8000)

## 7. 技术风险

| 风险 | 应对 |
|---|---|
| Java/Python跨语言调用 | HTTP API，简单可靠 |
| DAG引擎复杂 | 先实现顺序+分支，循环后续补 |
| Qdrant镜像拉不下来 | Mock模式 |
| 内存不足 | 不跑ClickHouse，用MySQL |
