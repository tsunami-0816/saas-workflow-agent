## 2. 整体分层架构

```
┌───────────────────────────── 接入层 ─────────────────────────────┐
│ 浏览器(Vue3+X6 画布 :5177)                                        │
│   ↓ HTTP/REST + SSE(:8083)            ↓ MQTT 设备消息(:1883)      │
│ java-backend(Spring Boot)              mosquitto                 │
└───────────────┬────────────────────────────────┬───────────────┘
┌───────────────▼────────────── 应用层 ──────────▼───────────────┐
│ java-backend :8083（单模块 Spring Boot）                        │
│  ├─ 租户/权限/额度/审计（多租户 + RBAC 三角色）                  │
│  ├─ 流程定义与版本管理（DSL JSON，status 字段留灰度锚点）        │
│  ├─ DAG 引擎（拓扑执行/分支/重试/延时/SSE 推送）                 │
│  ├─ 模型路由层（≥3 provider 统一接口 + token 计量）              │
│  ├─ 连接器 SPI（HTTP / MQTT 触发 / OCR-Mock）                   │
│  └─ NL→流程草稿（LLM 生成 DSL + JSON Schema 校验）              │
└───────┬───────────────────────┬────────────────────────────────┘
┌───────▼──────── 服务层 ───────▼────────────────────────────────┐
│ python-agent :8085（FastAPI + LangGraph + CrewAI）              │
│  └─ 三角色 Agent 编排（规划者/执行者/审核者），ReAct 推理链返回  │
│ RabbitMQ：execution.queue（流程异步执行）、agent 回调事件        │
└───────┬───────────────────────┬────────────────────────────────┘
┌───────▼──────── 计算/存储层 ──▼────────────────────────────────┐
│ MySQL 8 @3310(db=swa)：全部业务数据 + 执行记录 + 计量           │
│ Redis 7 @6381(db=3)：分布式锁(Lua)/幂等键/额度计数/流程状态缓存  │
│ Qdrant :6333：流程模板向量、相似执行记录检索                     │
└────────────────────────────────────────────────────────────────┘
┌────────────────────────── 运维层 ──────────────────────────────┐
│ docker-compose 编排 / Actuator 健康检查 / 结构化日志 /           │
│ LLM 成本台账(llm_call_log) / .env 配置管理                      │
└────────────────────────────────────────────────────────────────┘
```

各层职责：接入层只做协议接入与静态资源；应用层承载全部业务规则与 DAG 引擎（引擎内嵌 java-backend，避免第 6 个服务）；服务层承载 Agent 编排与异步消息；存储层全部共享/轻量实例；运维层零新增组件（不引入 Prometheus/Grafana，成本约束）。

## 3. 核心业务链路（端到端）

### L1 登录鉴权
浏览器提交账号密码 → `POST /api/v1/auth/login` → java-backend 校验用户表 → 签发 JWT（含 userId/tenantId/role）→ 前端存 token，后续请求带 `Authorization: Bearer`。

### L2 画布保存流程
X6 画布导出 nodes/edges → 前端组装 DSL JSON → `POST /api/v1/workflows/{id}/versions` → 服务端 JSON Schema 校验（节点类型合法/连线无环/入度出度正确）→ `workflow_version` 落库（status=draft）→ 返回版本号。**防丢验证（M1）**：重新打开时按 versionId 取回 DSL，X6 重渲染。

### L3 手动执行流程（MVP 主链路）
`POST /api/v1/executions {versionId}` → 幂等校验（Redis Lua `SETNX exec:idem:{userId}:{versionId}:{clientReqId}`）→ `execution` 落库(status=RUNNING) → 消息投 RabbitMQ `execution.queue` → java 内嵌 Worker 消费：解析 DSL → Kahn 拓扑排序 → 按序调度节点 Executor：
- **HTTP 节点**：连接器 SPI 调外部/Mock API，失败重试 ≤3 次（指数退避 1s/2s/4s），重试记录写 `node_execution.retry_log`（M3）
- **条件分支**：对上游输出做表达式求值，选定下游边
- **Agent 节点**：HTTP 调 python-agent `/agent/run`（详见 L5），超时 120s
- **代码块节点**：Java 内嵌 JS 沙箱（GraalVM JS，限制无 IO 权限）执行用户表达式
- **延时节点**：延迟队列（RabbitMQ TTL+DLX）到期后续跑
每个节点状态变更 → 写 `node_execution` + SSE 推送到前端画布节点变色 → 全部节点终态后 `execution.status=SUCCESS/FAILED`。

### L4 MQTT 触发流程（M6）
mosquitto 收到设备消息 → java-backend MQTT 客户端（Paho）按 `mqtt_subscription` 表匹配 topic → 反查绑定的 workflow_version → 走 L3 创建执行（消息 payload 作为流程入参）。端到端延迟 = 消息到达→`execution` 创建并首节点开始，打点计时，P95 ≤3s。

### L5 Agent 编排（硬骨头）
java → `POST python-agent:8085/agent/run {task, context}` → CrewAI Crew 启动：规划者 Agent（LangGraph 状态机分解子任务）→ 执行者 Agent（ReAct：工具调用-观察-推理循环）→ 审核者 Agent（校验输出格式与事实一致性）→ 各步推理链写入返回值 → python 侧调 LLM 统一走 java 模型路由层 `/internal/llm/chat`（保证计量集中）→ 结果回传 java → 写 `node_execution.output`。

### L6 模型路由与计量（M4）
`/internal/llm/chat {taskType, messages}` → 路由策略表（配置驱动：taskType→provider，如 规划→deepseek-chat）→ Provider 适配器 SPI（DeepSeek/OpenAI/Claude，后两者默认指向内嵌 Mock）→ 返回统一结构 `{content, promptTokens, completionTokens}` → 单价表折算成本 → 写 `llm_call_log` → BillingHook.afterCharge()（**空实现，扩展锚点**）→ 租户额度 Redis Lua 扣减，超额返回 429。

### L7 自然语言转流程（M5）
前端输入需求文本 → `POST /api/v1/workflows/nl-draft` → 模型路由层（Prompt 模板含 DSL Schema 与 few-shot）→ LLM 返回 DSL JSON → JSON Schema 校验（不合法则带错误重试 1 次）→ 存为 draft 版本 → 画布加载可编辑。

### L8 模板检索（配套）
流程保存时抽取摘要 embedding（远程 embedding API 或本地 sentence-transformers 小模型，第 5 步按内存实测二选一）→ 写 Qdrant → 画布「模板推荐」按语义召回。

## 4. 数据模型设计

统一规范：主键 `id BIGINT AUTO_INCREMENT`；全表带 `tenant_id BIGINT`（系统表除外）+ `created_at/updated_at DATETIME`；逻辑删除 `deleted TINYINT`；所有查询经 MyBatis-Plus 租户拦截器自动过滤。

| 表 | 关键字段 | 索引/说明 |
|---|---|---|
| tenant | name, status | uk(name) |
| user | tenant_id, username, password_hash, role | uk(tenant_id,username)；**role 单值**（admin/developer/viewer，每用户恰一角色） |
| tenant_quota | tenant_id, token_total, token_used | 额度与 Redis 计数对账 |
| audit_log | tenant_id, user_id, action, target, detail, ip | idx(tenant_id,created_at) |
| workflow | tenant_id, name, description | idx(tenant_id) |
| workflow_version | workflow_id, version_no, dsl_json(MEDIUMTEXT), status | uk(workflow_id,version_no)；**status∈draft/published/disabled（灰度锚点，本期只用 draft/published）** |
| execution | tenant_id, version_id, status, trigger_type, trigger_payload, started_at, ended_at | idx(tenant_id,status), idx(version_id) |
| node_execution | execution_id, node_id, node_type, status, input_json, output_json, retry_log, started_at, ended_at | idx(execution_id)；回放数据源 |
| llm_call_log | tenant_id, provider, model, task_type, prompt_tokens, completion_tokens, cost, latency_ms | idx(tenant_id,created_at)；M4 计量台账 |
| connector_credential | tenant_id, connector_type, config_json（密钥字段 AES 加密） | 连接器 SPI 配置仓 |
| mqtt_subscription | tenant_id, topic, workflow_version_id, status | uk(tenant_id,topic) |
| flow_template | tenant_id, workflow_id, summary, vector_id | Qdrant point id 映射 |

ER 关系：tenant 1─n user / workflow / tenant_quota 1─1；workflow 1─n workflow_version 1─n execution 1─n node_execution；mqtt_subscription n─1 workflow_version。

## 5. 接口规范定义

- 前缀 `/api/v1`；统一返回壳 `{code:0, message:"ok", data:{...}}`，业务错误 `code≠0`；HTTP 状态码语义化（401 未登录 / 403 越权或越角色 / 429 额度超限）。
- 错误码分段：`1xxxx` 通用参数；`2xxxx` 租户权限；`3xxxx` 流程定义/校验；`4xxxx` 执行引擎；`5xxxx` LLM 网关；`6xxxx` 连接器。
- 鉴权：JWT（Spring Security 过滤器链），tenantId/role 从 token claim 取，**禁止前端传 tenantId**。
- OpenAPI 契约：springdoc-openapi 自动生成 `/v3/api-docs`，第 6.5 步导出 `06.5_契约/openapi.json`。

核心接口清单（P0）：

| 方法 | 路径 | 说明 | 角色 |
|---|---|---|---|
| POST | /auth/login | 登录签 JWT | 公开 |
| GET/POST/PUT | /workflows, /workflows/{id}/versions | 流程与版本 CRUD | developer+ |
| POST | /workflows/nl-draft | NL→DSL 草稿 | developer+ |
| POST | /executions | 创建执行（幂等） | developer+ |
| GET | /executions/{id}，/executions/{id}/nodes | 执行详情/回放 | viewer+ |
| GET | /executions/{id}/events | SSE 进度订阅 | viewer+ |
| POST/GET | /mqtt-subscriptions | MQTT 触发绑定 | developer+ |
| GET | /quota，/llm-calls | 额度与计量台账 | admin |
| POST | /internal/llm/chat | 模型路由统一入口（仅内网/python-agent 调） | 内部 |

## 6. 部署架构设计

- **compose 服务（5 个，卡上限）**：java-backend(8083) / python-agent(8085) / rabbitmq(5672,15672) / mosquitto(1883) / qdrant(6333)。MySQL/Redis 用既有共享容器（3310/6381），前端本机 `vite dev`(5177)。
- **内存预算（16GB 总盘）**：MySQL 共享 ~500MB + Redis 共享 ~60MB + RabbitMQ ~450MB + Mosquitto ~20MB + Qdrant ~350MB + java(-Xmx768m) + python-agent ~400MB + vite ~600MB ≈ **3.1GB**，给 OS/IDE/浏览器留足余量。第 3 步 env_preflight 实测复核，超预算则按基线 R1 降级（Qdrant→MySQL 全文检索）。
- **高可用/扩缩容**：单机学习项目，不做 HA（显式说明）；M2 的 100 并发靠 Worker 线程池（默认 16）+ MQ prefetch 调优达成，不靠加实例。
- **环境划分**：仅 local 一套；`.env.example` 全量列出环境变量（第 6 步配置完整性校验）。

## 7. 监控与运维

- 健康探活：java `/actuator/health`、python `/health`（第 6 步探活脚本用）。
- 日志：logback(java)/loguru(python) 结构化 JSON，含 traceId（executionId 串联）。
- 指标：不引入独立监控栈（成本约束）；运行指标 = 库表直查（execution 状态统计、llm_call_log 成本台账、M6 延迟打点）。
- 告警：不配置（单机项目，显式排除）。

## 8. 技术风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| R1 内存 OOM（队列预警） | 高 | §6 内存预算表 + 第 3 步 env_preflight 实测；降级链：Qdrant→MySQL 全文检索，Mosquitto 已替代 EMQX |
| R2 CrewAI/LangGraph 版本兼容与 pip 源可用性 | 中 | 第 3 步 dependency_checker 机器校验；备选：CrewAI 不可用则自研轻量三角色编排（保留 LangGraph），不牺牲 JD 技能点 |
| R5 Mosquitto 无管理台 | 低 | 用 MQTT 客户端工具手测；订阅关系落库可查询 |
| R6 GraalVM JS 沙箱依赖体积 | 中 | 代码块节点若拖大镜像，降级为「表达式求值（Aviator/MVEL）」，节点类型数不变 |
| R7 100 并发下单 JVM 吞吐（M2） | 中 | Worker 线程池 + MQ prefetch 参数化，第 8 步压测调优；上下文全部走 DB/Redis，无内存态共享，天然隔离 |
| R8 LLM Mock 与真实协议漂移 | 低 | Mock 严格按 DeepSeek/OpenAI 官方响应结构实现，标注「协议替身」 |

## 9. 扩展锚点落位（基线 §3.3 用户确认项）

1. **Connector SPI**：`interface Connector { execute(config, input) }`，新 SaaS=新实现类+credential 配置。
2. **BillingHook**：`beforeCharge/afterCharge` 空实现挂在 L6 计量链路上。
3. **版本 status 字段**：draft/published/disabled，灰度期可加 publishing 态做流量切分。
4. **无方言 SQL**：编码规范写入第 4 步开发规范，评审与 CR 拦截。

## 10. 给第 4 步的模块分级预告（规则 18）

MVP 必达：L1 登录、L2 保存/重载、L3 执行主链路（HTTP/条件/Agent/延时节点+SSE）、L4 MQTT 触发、L5 三角色 Agent、L6 路由计量、多租户/RBAC 三角色。骨架不充 MVP。增强（可砍）：L8 模板检索、OCR 连接器（Mock）、审计查询页美化。
