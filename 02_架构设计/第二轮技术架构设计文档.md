## 2. 分层架构（同第一轮，此处固化）

- 接入层：Vue3+X6(:5177) → REST/SSE(:8083)；设备 → MQTT(:1883)
- 应用层（java-backend :8083）：租户/权限/额度/审计、流程版本管理、DAG 引擎、模型路由层、连接器 SPI、NL→流程
- 服务层：python-agent(:8085) 三角色 Agent 编排；RabbitMQ 异步执行
- 存储层：MySQL/Redis(共享) + Qdrant
- 运维层：compose 编排、Actuator/health 探活、结构化日志、llm_call_log 成本台账；不引入独立监控栈（成本）

## 3. 核心业务链路（修订处加粗）

- **L1 登录**：JWT（userId/tenantId/role claim），前端禁传 tenantId。
- **L2 保存流程**：DSL JSON → Schema 校验（类型合法/无环/入出度）→ workflow_version(status=draft/published/**disabled 锚点**)。
- **L3 执行**：幂等 `SETNX exec:idem:{user}:{ver}:{reqId}` → execution 落库 → MQ → Worker 拓扑调度；节点重试 ≤3（1s/2s/4s）写 retry_log；状态变更写 node_execution + SSE 推送。**新增：java-backend 启动时 sweeper 将超时 RUNNING execution 收敛为 FAILED(reason=engine_restart)（P1-1）。SSE 断线：前端按 executionId 拉 node_execution 快照后再续订（P2-4）。**
- **L4 MQTT 触发**：Paho 订阅（**QoS1，cleanSession=false，P2-1**）→ mqtt_subscription 反查 → 创建执行；打点验证 P95≤3s。
- **L5 Agent**：java → python `/agent/run`（超时 120s）→ CrewAI 规划/执行/审核 + ReAct 链 → **python 调 LLM 统一走 java `/internal/llm/chat`（超时 60s，失败计入 retry_log，P2-2）** → 结果回传。
- **L6 模型路由**：taskType→provider 配置路由 → 统一响应 → token×单价写 llm_call_log → Redis Lua 额度扣减（超 429）→ BillingHook 空实现（扩展锚点）。
- **L7 NL→流程**：few-shot + Schema 校验 + 带错重试 1 次 → draft。
- **L8 模板检索（配套）**：embedding 写 Qdrant；内存超支降级 MySQL 全文检索。

## 4. 数据模型（同第一轮 12 表，无变更）

tenant / user(role 单值) / tenant_quota / audit_log / workflow / workflow_version(status 锚点) / execution / node_execution / llm_call_log / connector_credential(AES) / mqtt_subscription / flow_template。全表 tenant_id + 逻辑删除 + MyBatis 租户拦截。

## 5. 接口规范（同第一轮）

`/api/v1` + 统一壳 `{code,message,data}` + 错误码分段 1xxxx~6xxxx + JWT + springdoc 自动契约（供第 6.5 步）。核心接口 9 组见第一轮 §5 表。

## 6. 部署架构（修订）

compose 5 服务：java-backend(8083) / python-agent(8085) / rabbitmq(5672,15672,**mem_limit=512m**) / mosquitto(1883) / qdrant(6333,**mem_limit=512m**)。内存总预算 ~3.1GB（本机当前可用 4.9GB，偏紧已记风险）。**镜像可拉取性为卡点复核遗留项：Docker daemon 就绪后补 `docker pull` 三镜像，失败则换国内镜像源前缀或按基线 R1 降级。** 单机无 HA；M2 并发靠 Worker 池 16 + MQ prefetch，step8 压测调优。

## 7. 监控与运维

健康探活 `/actuator/health`、`/health`；logback/loguru 结构化日志 traceId=executionId；运行指标库表直查（execution 统计、llm_call_log 成本、M6 打点）；不配独立告警栈。

## 8. 风险与应对（更新）

| 风险 | 等级 | 应对 |
|---|---|---|
| 可用内存 4.9GB 偏紧 | 高 | mem_limit 限额；降级链 Qdrant→MySQL 全文检索；起栈时关非必要应用 |
| Docker daemon/镜像拉取未验 | 中 | 卡点复核项，补 docker pull 实测 |
| CrewAI/LangGraph 1.x 新大版本 API 变动 | 中 | 已钉版复验存在；第 5A 步先写最小 Crew 跑通再扩展 |
| 100 并发吞吐 | 中 | 池化参数化，step8 压测 |
| LLM Mock 协议漂移 | 低 | 按官方响应结构实现并标注 |
