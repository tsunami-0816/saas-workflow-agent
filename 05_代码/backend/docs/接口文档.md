# saas-workflow-agent 接口文档（BE / 5A 产物）

> Base URL：`http://localhost:8083`。本文档与代码同步维护；在线 OpenAPI 见 `/swagger-ui/index.html`（springdoc 2.5.0）。

## 0. 通用约定

### 0.1 认证

- 登录后所有 `/api/v1/**` 接口需携带请求头：`Authorization: Bearer <token>`（JWT，HS256，claim 含 userId/tenantId/role）。
- 内部接口 `/internal/**` 不校验 JWT，校验请求头 `X-Internal-Token`（与 env `INTERNAL_API_TOKEN` 一致），否则 401。
- 角色取值：`admin`（全部权限）、`dev`（读写业务资源）、`viewer`（只读）。`tenantId` 一律以 token claim 为准，传参忽略。

### 0.2 统一响应壳

```json
{ "code": 0, "message": "ok", "data": {} }
```

- 成功：`code = 0`。
- 失败：`code` 为业务错误码（见 0.4），`message` 为说明，`data` 为 null。

### 0.3 HTTP 状态码映射

| 场景 | HTTP | code |
| --- | --- | --- |
| 成功 / 一般业务失败 | 200 | 0 / 业务码 |
| 未登录或 token 失效 | 401 | 10401 |
| 已登录但角色越权 | 403 | 10403 |
| 租户额度超限 | 429 | 40429 |

### 0.4 错误码总表（分段）

| code | 含义 |
| --- | --- |
| 10000 | 参数错误 |
| 10004 | 资源不存在 |
| 10401 | 未登录或凭证已失效 |
| 10403 | 越权访问：角色无权执行该操作 |
| 10500 | 服务器内部错误 |
| 20001 | 流程不存在 |
| 20002 | DSL 校验失败：存在环形依赖 |
| 20003 | DSL 校验失败：未知节点类型 |
| 20004 | DSL 校验失败：节点入度/出度不合法 |
| 20005 | DSL 校验失败：连线指向不存在的节点 |
| 20006 | DSL 校验失败（通用） |
| 20007 | 流程版本不存在 |
| 20008 | 流程版本已禁用，不可执行 |
| 20009 | 仅 published 状态版本可执行 |
| 20010 | 版本状态流转非法 |
| 30001 | 执行实例不存在 |
| 30002 | 执行创建失败（含幂等占坑冲突） |
| 30003 | 节点执行失败 |
| 40001 | LLM 调用失败 |
| 40002 | 未知 taskType 或未配置路由 |
| 40003 | NL 生成流程失败（含一次带错重试后仍失败） |
| 40429 | 租户额度超限 |
| 50001 | 连接器不存在 |
| 50002 | 连接器凭据不存在 |
| 50003 | MQTT 订阅不存在 |
| 50004 | HTTP 节点调用失败（节点内重试 ≤3 次后上抛） |
| 60001 | Agent 调用失败或超时 |

### 0.5 分页参数

分页接口统一 query：`pageNo`（默认 1）、`pageSize`（默认 20）。响应 `data` 为 MyBatis-Plus Page：`{ "records": [], "total": 0, "current": 1, "size": 20 }`。

## 1. 认证（/api/v1/auth）

### POST /api/v1/auth/login

登录签发 JWT。无需认证。

请求：

```json
{ "username": "dev_acme", "password": "Swa@123456" }
```

响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": { "token": "eyJhbGciOi...", "userId": 2, "tenantId": 1, "username": "dev_acme", "role": "dev" }
}
```

错误码：10401（账号或密码错误 / 账号已停用）。

### GET /api/v1/auth/me

当前登录用户信息。三角色均可。

响应 `data`：`{ "userId": 2, "tenantId": 1, "username": "dev_acme", "role": "dev" }`

## 4. 流程管理（/api/v1/workflows）

### 4.1 流程 CRUD

| 方法 | 路径 | 角色 | 说明 |
| --- | --- | --- | --- |
| GET | /api/v1/workflows?pageNo=&pageSize=&name= | 三角色 | 流程分页列表 |
| GET | /api/v1/workflows/{id} | 三角色 | 流程详情 |
| POST | /api/v1/workflows | admin/dev | 创建流程（审计 workflow.create） |
| PUT | /api/v1/workflows/{id} | admin/dev | 更新流程（审计 workflow.update） |
| DELETE | /api/v1/workflows/{id} | admin/dev | 删除流程（审计 workflow.delete） |

创建请求：

```json
{ "name": "设备高温告警流程", "description": "MQTT 温度超阈值触发告警" }
```

### 4.2 版本管理

| 方法 | 路径 | 角色 | 说明 |
| --- | --- | --- | --- |
| GET | /api/v1/workflows/{id}/versions | 三角色 | 版本分页 |
| POST | /api/v1/workflows/{id}/versions | admin/dev | 保存新版本（DSL Schema 校验，状态 draft） |
| GET | /api/v1/workflows/versions/{versionId} | 三角色 | 版本详情 |
| PUT | /api/v1/workflows/versions/{versionId}/publish | admin/dev | 发布（draft→published） |
| PUT | /api/v1/workflows/versions/{versionId}/disable | admin/dev | 禁用（published→disabled，灰度锚点） |

保存版本请求：

```json
{
  "dslJson": "{\"nodes\":[{\"id\":\"t1\",\"type\":\"mqtt-trigger\",\"name\":\"温度采集\",\"config\":{}}],\"edges\":[]}"
}
```

DSL 结构：`{ "nodes": [{ "id", "type", "name", "config" }], "edges": [{ "source", "target", "branch" }] }`。节点类型（与 DslValidator 口径一致，共 6 类）：`mqtt-trigger / condition / http / code / delay / agent`。校验失败返回 20002~20006；状态流转非法返回 20010。

### 4.3 NL→流程草稿

`POST /api/v1/workflows/nl-draft`（admin/dev，审计 workflow.nl-draft）

请求：

```json
{ "text": "收到工厂温度消息后，超过 80 度就调用告警接口，否则记录正常", "workflowName": "设备高温告警流程" }
```

行为：LLM 生成 DSL → Schema 校验 → 失败带错误重试 1 次 → 仍失败抛 40003；成功则创建流程并保存 draft 版本，响应 `data` 为版本对象（含 dslJson）。

错误码：40001（LLM 调用失败）、40002（taskType 未配置路由）、40003、40429（额度超限）。

## 5. 执行（/api/v1/executions）

| 方法 | 路径 | 角色 | 说明 |
| --- | --- | --- | --- |
| POST | /api/v1/executions | admin/dev | 创建执行（审计 execution.create，幂等） |
| GET | /api/v1/executions?pageNo=&pageSize=&status= | 三角色 | 执行分页（status 可选） |
| GET | /api/v1/executions/{id} | 三角色 | 执行详情 |
| GET | /api/v1/executions/{id}/nodes | 三角色 | 节点执行快照列表 |
| GET | /api/v1/executions/{id}/events | 三角色 | SSE 订阅节点/执行事件 |
| POST | /api/v1/executions/{id}/replay | admin/dev | 重放（复制触发入参新建执行，审计 execution.replay） |

创建请求：

```json
{ "versionId": 1, "clientReqId": "req-20261028-001", "triggerPayload": "{\"temp\": 95}" }
```

- 幂等：`exec:idem:{userId}:{versionId}:{clientReqId}` SETNX（TTL 24h），重复提交返回已存在的执行实例。
- 版本非 published → 20009；已 disabled → 20008。

执行对象 `status ∈ RUNNING/SUCCESS/FAILED/WAITING`；`failReason` 记录收敛原因（node_failed / engine_restart / engine_error / engine_deadlock）。

节点快照 `data` 示例：

```json
[
  { "nodeId": "t1", "nodeType": "mqtt-trigger", "status": "SUCCESS", "inputJson": "{\"_payload\":{\"temp\":95}}", "outputJson": "{\"payload\":{\"temp\":95}}", "retryLog": null, "errorMessage": null }
]
```

SSE（`text/event-stream`）事件名：`connected`（连接建立）、`node`（节点状态变更，data 为节点快照 JSON）、`execution`（执行状态变更）。超时 30 分钟。

错误码：30001（执行不存在，含跨租户）、30002（幂等占坑冲突，需更换 clientReqId）。

## 6. MQTT 订阅（/api/v1/mqtt/subscriptions）

| 方法 | 路径 | 角色 | 说明 |
| --- | --- | --- | --- |
| GET | /api/v1/mqtt/subscriptions?pageNo=&pageSize= | 三角色 | 订阅分页 |
| GET | /api/v1/mqtt/subscriptions/{id} | 三角色 | 详情 |
| POST | /api/v1/mqtt/subscriptions | admin/dev | 创建（审计 mqtt.subscription.create，写后热重订阅） |
| PUT | /api/v1/mqtt/subscriptions/{id} | admin/dev | 更新（审计 mqtt.subscription.update） |
| DELETE | /api/v1/mqtt/subscriptions/{id} | admin/dev | 删除（审计 mqtt.subscription.delete） |

请求：

```json
{ "topic": "factory/+/temperature", "workflowVersionId": 1, "status": "active" }
```

- `(tenantId, topic)` 唯一，冲突返回 10000「topic 已存在」。
- 绑定的版本不存在 → 20007；订阅不存在 → 50003。
- 消息到达后按 topic 通配匹配创建执行（triggerType=mqtt，clientReqId 自动派生 `mqtt-{subId}-{md5(payload)}`）。

## 9. 内部接口：模型路由（/internal/llm/chat）

python-agent → java-backend 的统一 LLM 出口。校验 `X-Internal-Token`，不校验 JWT。

请求：

```json
{
  "taskType": "agent_reasoning",
  "messages": [{ "role": "user", "content": "..." }],
  "provider": null
}
```

响应（HTTP 恒 200，成功码 `{0, 200}` 兼容 python 侧判定）：

```json
{
  "code": 0,
  "message": "ok",
  "data": { "content": "...", "provider": "deepseek", "model": "deepseek-chat", "promptTokens": 10, "completionTokens": 20 }
}
```

行为：按 `taskType` 路由 provider（`llm.routes` 配置，`provider` 字段可强制指定）→ 调用 → 写 llm_call_log 台账 → Redis Lua 原子扣减额度（key 缺失时用 DB 剩余惰性初始化；不足返回 40429）→ 同步 tenant_quota.token_used → BillingHook 计费回调（当前为 Noop 占位）。

错误码：40001（LLM 调用失败）、40002（未知 taskType）、40429（额度超限）。

> **租户透传（第 7 步已联调确认）**：本接口接受可选请求头 `X-Tenant-Id` 注入租户上下文。python-agent 侧已全链透传（AgentNodeExecutor → `/agent/run.tenantId` → LangGraph state → `JavaLLMClient.chat()` 带 `X-Tenant-Id`）；实测台账 `tenant_id=1`，额度/DB/Redis 三方计量一致。缺省（无该头）时 tenantId=0 占位、写台账但跳过额度扣减并输出 warn 日志。

## 10. java-backend → python-agent 契约（出向，供参考）

`POST {python-agent-url}/agent/run`（无鉴权，内网信任）：

```json
{ "executionId": "123", "nodeId": "a1", "task": "...", "inputData": {}, "constraints": {}, "taskType": "agent_reasoning" }
```

响应（恒 200）：

```json
{ "status": "SUCCESS", "output": {}, "reasoning": "...", "error": null, "durationMs": 120 }
```

`status != SUCCESS` 时 java 侧按节点失败处理（可重试 ≤3 次）。
